# PassPick (패스픽)

대학생 맞춤형 자격증 시험 조건 탐색 및 D-Day 관리 서비스

> **문서 버전:** PRD v0.5
> **형태:** 웹 기반 모바일 퍼스트(402pt, iPhone 17 기준) 자격증 탐색 및 개인화 일정 관리 서비스

## 1. 프로젝트 개요

### 1.1 문제 정의

- 자격증 준비 시 **응시 자격(전공·학년 제한), 시험 일정(정기·상시), 응시료, 난이도** 정보가 시행처 사이트마다 흩어져 있어 비교에 시간이 많이 듭니다.
- 시험 일정을 등록해도 텍스트 D-Day만으로는 접수 마감 여부나 남은 준비 기간을 직관적으로 알기 어렵습니다.

### 1.2 핵심 가치

| 가치 | 내용 |
| :--- | :--- |
| 조건 중심 빠른 탐색 | 300건의 자격증 데이터를 분야·응시자격·난이도 필터, 정렬, 키워드 검색으로 빠르게 탐색 |
| 직관적 일정 관리 | D-Day, 준비 진행률 프로그레스 바, 접수 상태 배지(`정기` `상시` `접수 마감` `일정 확인 필요`) 제공 |
| 개인 상태 관리 | 목표 D-Day 등록과 `준비중` / `합격` 취득 상태를 마이 페이지에서 탭별로 관리 |

## 2. 화면별 요구사항

하단 고정 내비게이션은 **홈 · 검색 · 마이** 3개 탭으로 구성합니다.

### 2.1 홈 (`#v-home`)

- **브랜드 헤더:** `PassPick` 로고 고정 노출
- **목표 D-Day 영역** (등록한 목표 시험 수에 따라 표시가 달라집니다)
  - **0건:** `나의 목표 D-Day` / `미등록` 배지 / `D-?` 와 함께 등록을 권유하는 안내 문구, `D-Day 등록하기` 버튼(검색 탭으로 이동)
  - **1건 (히어로 카드):** 자격증명, 큰 `D-Day`, 접수 상태 배지(`접수 중` / `접수 예정` / `접수 마감`), 진행률 프로그레스 바, 시험일(`YYYY-MM-DD`)과 원서 접수 기간(`MM.DD ~ MM.DD`), 메타 요약(분야 › 세부 분야, 응시자격, 3단계 난이도, 응시료), `＋ 비교할 목표 시험 더 추가하기` 버튼
  - **2~3건:** 작은 D-Day 카드를 나란히 표시 (시험일이 가까운 순)
- **원서 접수 임박 시험:** 마감 임박 목록, `전체보기` 링크, 유형 배지(`정기`/`상시`), D-Day 배지
- **대학생 인기 자격증 Top 5:** 인기순 상위 5개, 1~5위 순위 숫자를 카드 안에 표시

### 2.2 검색 (`#v-list`)

- **통합 검색창 (`#q`):** 자격증명 키워드 실시간 검색
- **필터:** `분야 ▾` / `응시자격 ▾` / `난이도 ▾` 알약 버튼 3개. 누르면 선택지가 펼쳐지고, 고른 값은 버튼에 표시됩니다.
  - **분야(상위) → 세부 분야(하위) 구분:** 분야를 고르면 같은 영역 안에 세부 분야가 이어서 나옵니다.
  - 세부 분야 예: IT/컴퓨터 = 보안·네트워크 / 데이터 / 개발·SW / 사무·디자인, 어학 = 영어 / 일본어 / 중국어 / 기타 외국어, 전문직 = 법·회계·세무 / 부동산·유통 / 상담·복지·교육 / 의료·보건, 공기업 = 한국사·국어 / 금융·투자 / 회계·세무 / 사무·무역, 사무/자격 = 컴퓨터·OA / ERP·실무 / 한자, 기타 = 자동차 / 건설기계 / 기계·설비 / 전기·철도·승강기 / 농림·조경
- **정렬:** `마감 임박순`, `응시료순`, `인기순` 3종. 결과 건수와 `초기화` 링크를 같은 줄에 표시합니다.
  - 인기순은 실제 응시자 통계가 아니라 대학생 인기를 기준으로 직접 선정한 62개 순위이며, 목록에 없는 자격증은 뒤에 배치됩니다. 인기순일 때 카드 안에 순위 숫자가 표시됩니다.
- **목록 카드:** 자격증명, 시험 유형 배지(`정기`/`상시`), D-Day 배지, 한 줄 메타 정보 `분야 › 세부 분야 · 응시자격 · 난이도 ●●○` (응시료는 `응시료순` 정렬일 때만 함께 표시)
- **화면 상태:** 초기 · 로딩 · 결과 없음(조건 줄이기 안내, 초기화 버튼) · 오류(로컬 저장 데이터 유지)

### 2.3 상세 정보 모달 (`#modal`)

- **헤더 (v0.4 개선):** 자격증명과 함께 우측 상단 `닫기 X` 태그 스타일 버튼으로 변경해 가독성과 터치 편의성 강화. 닫아도 이전 검색어·필터·스크롤 위치 유지
- **회차별 일정 (v0.4 개선):** 다회차 시험은 라디오로 선택하고, 각 회차의 접수 기간·시험일과 함께 `정기` 배지, `D-4` 같은 잔여 일수 배지를 함께 표시
- **상세 정보 (v0.4 정돈):** 응시자격 안내 / 응시료 / `공식 일정 안내 ↗` / 키워드 태그(예: `IT/컴퓨터 · 고급 · 디지털 역량`)를 구분선으로 나눠 가독성 향상
- **하단 고정 액션 바 (Sticky Bottom):** `공식 접수처 바로가기 ↗` 아웃링크 버튼과 검은색 `목표 D-Day 등록 / 취소` 토글 버튼

### 2.4 마이 (`#v-my`)

- **2탭 구조:** `목표 D-Day` 탭과 `취득 상태` 탭으로 분리해 원하는 정보를 탭별로 관리
- **목표 D-Day 탭**
  - 등록 건수 표시(예: `등록 1건`)
  - 개별 자격증 `삭제` 버튼, `전체 초기화` 버튼
  - 0건일 때는 빈 화면 대신 탐색 이동 버튼 제공
- **취득 상태 탭**
  - 자격증별로 `준비중` / `합격` 상태를 선택 버튼으로 변경
  - **선택 삭제:** 목록 위 `삭제` 버튼 → 각 줄에 체크박스 표시 → `전체 선택`(다시 누르면 전체 해제) / `취소` / `선택 삭제 (n)` → 확인 후 삭제. 선택이 0개이면 `선택 삭제` 버튼은 비활성화됩니다.
- 저장은 현재 브라우저 `localStorage` 기반

### 2.5 공통 레이아웃

- **화면 크기:** iPhone 17 기준 402×874pt. 실제 폰에서는 화면을 꽉 채우고 상단·하단 안전 영역(safe-area)을 적용하며, PC 브라우저에서는 기기 프레임 없이 402px 폭(최대 높이 874px) 화면만 가운데에 표시합니다.
- **하단 탭 고정:** 하단 내비게이션은 탭을 바꿔도 같은 위치에 고정되고, 내용은 그 위 영역 안에서만 스크롤됩니다.

## 3. 데이터 설계 및 구조

### 3.1 디렉토리 구조

저장소 루트에 아래와 같이 둡니다. (`index.html`이 루트에 있어야 GitHub Pages로 배포됩니다.)

```text
(저장소 루트)
├── index.html              # 진입점 (상단 바, 하단 탭, 모달 컨테이너, 화면이 들어올 #pages)
├── css/
│   └── style.css           # 모바일 퍼스트 스타일, 배지/카드/필터 UI
├── data/
│   ├── certificates.json   # 300건 자격증 데이터셋 (앱이 먼저 읽음)
│   └── certificates.js     # 같은 데이터 (json을 읽지 못할 때 대체)
├── js/
│   ├── app.js              # 검색/필터/정렬, D-Day 계산, 상태 관리(store 계층), pages 불러오기
│   └── firebase-config.js  # Firebase 웹 앱 설정값 (v0.6에서 index.html에 연결 예정)
├── pages/
│   ├── home.html           # 홈 화면 (#v-home)
│   ├── search.html         # 검색 화면 (#v-list)
│   └── my.html             # 마이 화면 (#v-my)
├── README.md
└── RESEARCH_REPORT.md      # 시험 일정 조사 보고서
```

### 3.2 자격증 데이터 스키마 (`certificates`)

| 필드 | 자료형 | 설명 |
| :--- | :--- | :--- |
| `id` | Number | 고유 식별자 (`targetExams`, `myCertStatus` 매핑 키) |
| `name` | String | 자격증명 (목록·검색 대상) |
| `field` | String | 분야 (`IT/컴퓨터`, `어학`, `전문직`, `공기업`, `사무/자격`, `기타`) |
| `eligibility` | String | 응시자격 (`제한없음` / `응시자격 확인 필요`) |
| `eligibilityText` | String | 응시자격 상세 안내 문구 |
| `difficulty` | Number (1~3) | 난이도 (`●○○` / `●●○` / `●●●`) |
| `level` | String | 등급 (`초급` / `중급` / `고급`) |
| `fee` | Number | 응시료(원), 응시료순 정렬 기준 |
| `rounds` | Array | 회차별 `[접수 시작일, 접수 마감일, 시험일]` (`YYYY-MM-DD`). 앱에서 `roundId`를 붙여 사용 |
| `examDates` / `nextExamDate` | Array / String | 시험일 목록 / 다음 시험일 |
| `scheduleType` | String | 운영 형태 (`scheduled`, `scheduled_periodic`, `continuous`(상시), `multiple_sessions`, `not_in_next_round`, `unverified`) |
| `overview` | String | 상세 모달용 개요 |
| `tags` | Array\<String\> | 키워드 태그 (예: `IT/컴퓨터`, `고급`, `디지털 역량`) |
| `officialUrl` | String (URL) | 공식 접수처·안내 링크 |
| `feeSourceUrl` · `scheduleSourceUrl` | String (URL) | 응시료·일정 출처 링크 |
| `researchStatus`, `scheduleNote` 등 | Object / String | 응시료·일정 조사 상태와 확인일 메타데이터 |

> **소분류·인기순은 데이터 필드가 아닙니다.** 세부 분야는 자격증 이름 키워드로 분류하는 `js/app.js`의 `SUBS`, 인기순은 직접 선정한 62개 순위 목록 `POP`으로 계산합니다.

### 3.3 개인화 데이터 저장

| 키 | 내용 |
| :--- | :--- |
| `targetExams` | 목표 D-Day로 등록한 자격증 (`"자격증id:회차id"` 문자열 배열) |
| `myCertStatus` | 자격증별 `준비중` / `합격` 상태 (`{자격증id: 상태}`) |

현재는 브라우저 `localStorage`에 저장됩니다. 읽기·쓰기는 모두 `js/app.js`의 `store` 계층(`getT`/`getS`/`setT`/`setS`)을 거치며, 저장할 때마다 `syncHooks`에 등록된 함수가 호출되는 구조입니다. v0.6에서 이 자리에 클라우드 저장 함수를 등록합니다. 훅이 실패해도 로컬 저장과 화면에는 영향이 없습니다.

## 4. 향후 계획: 클라우드 동기화 (v0.6 예정)

> 아직 앱에 연결되어 있지 않습니다. v0.5에서 준비를 마쳤고, v0.6에서 구현합니다.

**배경:** `localStorage`에만 저장하면 브라우저 데이터를 지웠을 때 기록이 사라지고, PC·모바일 간에 일정을 이어 볼 수 없습니다.

### 4.1 v0.5에서 준비한 것

- Firebase 웹 앱 등록, 설정값 `js/firebase-config.js` (`firebaseConfig`는 공개돼도 되는 식별 정보이며, 접근 제어는 보안 규칙이 담당)
- Authentication **익명 로그인** 사용 설정 (가입·이메일·비밀번호 없음)
- Firestore 생성(프로덕션 모드) 및 보안 규칙 게시
- 앱의 저장 구조 정리(`store` / `syncHooks`)

### 4.2 설계: 익명 로그인 + 연동 코드 + Local-First

- **개인정보를 받지 않습니다.** 학번·이름 대신, 앱이 만든 랜덤 **연동 코드**(예: `K7M2-QX9P`)로 데이터를 구분합니다. 저장하는 값은 `targetExams`, `myCertStatus`, `updatedAt`뿐입니다.
- **연동 코드가 필요한 이유:** 익명 계정의 ID는 브라우저 안에 저장되어, 캐시를 지우면 함께 사라집니다. 사용자가 연동 코드를 따로 보관해야 데이터 복구와 기기 간 동기화가 가능합니다.
- **저장 위치:** Firestore `sync/{연동 코드}` 문서 1개

**동작 흐름**

1. **Local-First:** 화면은 항상 `localStorage`를 기준으로 즉시 그립니다.
2. **백그라운드 저장:** 저장할 때마다 `syncHooks`를 통해 Firestore에 비동기로 올립니다.
3. **연동:** 다른 기기에서 연동 코드를 입력하면 클라우드 데이터를 불러옵니다. 기기와 클라우드 데이터가 모두 있으면 덮어쓰지 않고 **합칩니다**(목표는 합집합, 상태는 `합격` 우선).
4. **Graceful Fallback:** 오프라인·지연·DB 오류가 나도 앱은 멈추지 않고 `localStorage`로 정상 동작하며, 마이 화면에 동기화 상태(`동기화됨` / `오프라인: 이 기기에만 저장 중`)를 표시합니다.

### 4.3 보안 규칙 (적용 완료)

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /sync/{code} {
      allow get: if request.auth != null;
      allow create, update: if request.auth != null
        && request.resource.data.keys().hasOnly(['targetExams','myCertStatus','updatedAt'])
        && request.resource.data.targetExams is list
        && request.resource.data.targetExams.size() <= 50
        && request.resource.data.myCertStatus is map;
      allow list, delete: if false;
    }
  }
}
```

로그인(익명 포함)한 사용자만 `sync/{코드}` 문서를 읽고 쓸 수 있습니다. 문서 목록 조회와 삭제는 막아서 연동 코드를 모르면 다른 사람의 데이터를 찾을 수 없고, 저장 가능한 항목과 크기도 제한합니다.

## 5. 실행 방법

화면(`pages/`)을 파일에서 불러오는 구조라서 **`index.html`을 더블클릭해서 열면 동작하지 않습니다.** (화면 파일을 불러오지 못했다는 안내가 표시됩니다.) 아래 중 한 가지로 실행합니다.

1. **로컬 서버:** 저장소 루트에서 `python3 -m http.server 8000` 실행 후 브라우저에서 `http://localhost:8000` 접속
2. **GitHub Pages:** 저장소 루트에 `index.html`, `css/`, `data/`, `js/`, `pages/`가 함께 있도록 올리면 그대로 동작합니다.
